## 1. What is being built

The v3 town layout is **approved as a picture** (`docs/town_map_v3.png`, generated by
`tools/town_plan_v3.py`). No game code has been changed for it yet. This plan turns the picture
into the game, **built from the bought asset kit, not from primitives.**

v3 in brief (the generator file is the full specification; read it if your lane needs geometry):

- Same extent, river, railway, station, bridges, landmarks and market square as v1.
- Ring road and through roads snapped so **every road segment is axis-aligned or 45°**. 95 roads.
  Roads with `head=True` end in a cul-de-sac turning head.
- Plots: 1 unmoved, 2 and 4 pulled toward the ring, **3 moved to the south-west** in Westdale.
- **Everything built is generated from street frontage**: housing, shops, flats, workshops,
  warehouses, corner shops. One building deep, parallel to its street. About 35 special blocks
  (church, town hall, schools, pubs, marina, park, sports centre…) are still hand-placed data.
- Building types are a table (`TYPES`): terraced row, semis, detached house, corner shop, shops
  with flats, shops, flats, workshop, trade counter, warehouse.

## 2. The rule that matters most: NO PRIMITIVES

The owner's instruction, verbatim in spirit: *primitives should basically be banned; the town must
be as asset-filled as the vertical slice.*

The slice is `Workspace.VerticalSlice` (review spawn `(2986, 1, 2170)`), reproducible from
`tools/kit/place_slice_{A_fences,C_street,D_props}.luau`. **That is the density and look to match.**
Read `docs/SLICE_PLAN.md` and look at the slice in Studio before building anything.

What "no primitives" means in practice:

1. Anything a player sees as an *object* (building, road surface, kerbside prop, wall, fence, sign,
   lamp, vehicle) comes from `ServerStorage.Kit` via `KitPlacer.place/row`. 497 assets are uploaded:
   355 UK Street Props (incl. 44 `ModularRoads`), 83 Modular English Housing (6 prefab houses × 2
   trims + **68 modular pieces**), 26 Poly Haven, plus Creator Store keepers. Inventory:
   `docs/ASSET_INVENTORY.md`. **Step zero for everyone: confirm `ServerStorage.Kit.Meshes` holds all
   of them; if it holds ~96, run `assets/kit/_export/fetch_kit.luau` first.**
2. Primitives are allowed ONLY for: terrain-like ground (grass, water, the pitch), invisible
   collision/trigger volumes, and gaps listed in the **Primitive Exceptions Register** (section 7).
   Adding to the register requires naming the missing asset, so the owner can buy or generate it.
3. `KitPlacer` falls back to a grey block on a missing name and tags it `KitMissing`. **A finished
   lane has zero `KitMissing` instances.** Every lane's tests assert this.
4. If the kit has no asset for something (known gaps: shopfront units, pub/station/industrial
   buildings, kerbs, roundabout, flats), do NOT quietly build it from Parts. First try assembling
   it from MEH modular pieces + UKSP walls/shutters; if that fails, add it to the register and to
   the buy list in section 8, and leave the simplest possible stand-in.
5. Textures: SurfaceAppearance maps above 1024² render flat grey. If a kit piece looks grey in
   Studio, it is an export problem (`max_tex: 2048` in `build_jobs.py`), not a reason to use a Part.

### The honest constraint: performance

On 2026-09-19 the opposite call was made (town stays primitive) because town-scale part budgets
(1,240 / 900 / 260) could not afford meshes. The owner has now overruled that, so **performance is
Lane P's whole job and a gate for everyone**, not an afterthought. Things in our favour:
`StreamingEnabled` is already on; MeshParts sharing a MeshId are instanced by the renderer; a
terrace assembled from 6 repeated modules is far cheaper than it looks. Lane P sets the numbers.
Until Lane P publishes them in section 9, use the TEMP budgets there.

## 3. How parallel work is organised

**Yes, this runs in parallel, but there is ONE Roblox Studio and ONE Rojo session**, and that
shapes everything. The model is: **one shared checkout, strict file ownership, sandboxed building.**

- All agents work in `F:\dev\football-club-tycoon` on the same branch. No worktrees (a second
  worktree cannot sync to the one Studio).
- **You may only create or edit the files your lane owns** (listed per lane). Need a change in
  someone else's file? Write it in `docs/TOWN_V3_HANDOFFS.md` under their lane. Do not edit it.
- Shared files (`TownLayout.luau`, `Main.server.luau`, `WorldBuilder.luau`, `TownBuilder.luau`,
  `tests/RunAll`) belong to **Lane A / the Integrator only**.
- Commit only your own paths: `git add <your files>`; never `git add -A`. If git reports an index
  lock, wait and retry: another agent is mid-commit.
- **Rojo needs a manual Disconnect/Connect when files are ADDED.** So Lane A creates every lane's
  stub files in Wave 0 and Marcel reconnects once. After that, everyone only edits existing files,
  which hot-sync. If you truly need a new file later, batch the request in the handoffs doc.
- **Sandbox building.** Builder lanes develop in Studio **Edit mode** by calling their module's
  build function into their own folder `Workspace.V3Sandbox.<Lane>` at their own origin (section 6
  gives each lane an origin far from the live town and the slice). Never build into, or delete from,
  another lane's folder, `Workspace.VerticalSlice`, or the runtime town.
- **Only the Integrator starts/stops Play.** Builder lanes never call `start_stop_play`; a playtest
  resets everyone's Edit-mode sandbox view and hijacks the shared Studio.
- Run only your own test module while developing:
  `loadstring(game.ServerStorage.Tests.<YourTest>.Source)()` style, matching how `RunAll` invokes
  modules. The full `RunAll` (632 passing today) is the Integrator's job. The MCP sandbox needs the
  `DebugRun` attribute.
- No local Luau parser exists. `loadstring(source)` in Studio is the only syntax check; do it for
  every file you touch before you commit.
- Do not write Lua through Bash heredocs (escapes and apostrophes break). Use Write/Edit.
- Questions for Marcel: batch them, numbered, each with your recommendation, in
  `docs/TOWN_V3_HANDOFFS.md` under "Questions". He answers by voice in one pass.

## 4. The contract (fixed; change only via Lane A)

### 4.1 `TownLayout` (src/shared/TownLayout.luau) — Lane A

```lua
export type Road = {
    name: string, kind: "ring"|"main"|"residential"|"lane", width: number,
    points: { Vector3 },
    front: "both"|"left"|"right"|"none",   -- left of the direction of travel
    use: string?,                            -- a TYPES key; nil when useAt decides
    useAt: string?,                          -- name of a rule in TownFrontage.RULES ("centre", "industrial", ...)
    district: string?,
    head: boolean?,                          -- last point is a cul-de-sac turning head
}
TownLayout.HEAD_RADIUS = 34
```

`DISTRICTS` shrinks to the hand-placed special blocks only. Everything else keeps its v1 shape.

### 4.2 `TownFrontage` (src/shared/TownFrontage.luau) — Lane A

Pure data, deterministic, no Instances.

```lua
export type Lot = {
    id: string,            -- stable: "<road name>|<side>|<segment index>|<n>"
    use: string,           -- TYPES key
    district: string,
    street: string,        -- road name it fronts
    centre: Vector3,       -- ground level, centre of the footprint
    size: Vector3,         -- X = frontage length along the street, Z = depth, Y = nominal height
    yaw: number,           -- degrees; local +X runs along the street
    front: Vector3,        -- unit vector pointing FROM the lot TO its street (doors face this way)
    units: number,         -- houses/shops in this lot (a terraced row of 6 has units = 6)
    unitWidth: number,     -- frontage per unit
    closesStreet: boolean, -- the row across the end of a cul-de-sac
    corner: boolean,       -- first/last lot before a junction (corner shops, gable ends)
}
TownFrontage.TYPES   -- [use] = { cell, depth, group, gap, garden, height }
TownFrontage.generate(): { Lot }          -- cached
TownFrontage.lotsByDistrict(): { [string]: { Lot } }
TownFrontage.lotsByUse(use: string): { Lot }
```

Until Lane A's Luau lands, Wave 1 lanes can dump the same data from Python:
`python tools/town_plan_v3.py --json` (Lane A adds this flag first thing) writes
`docs/town_v3_lots.json` with roads and lots in exactly this shape.

### 4.3 Builder module shape — every Wave 1 builder lane

```lua
local M = {}
M.PART_BUDGET = <number>                       -- from section 9
-- Builds everything this lane owns under `parent`. `origin` offsets the whole town so the
-- same code builds the sandbox and the live town. Returns counts for the [FCT] summary line.
function M.build(parent: Instance, origin: CFrame, filter: { district: string? }?): { [string]: number }
return M
```

Rules: read `TownLayout`/`TownFrontage` only, never each other. Deterministic (seed any variety
from `Lot.id`). Group output in one Model per district with `ModelStreamingMode = Atomic` unless
Lane P says otherwise. Print one `[FCT] <Lane>: ...` summary line. `filter.district` must work, so a
single district can be built for review.

   wire, anything added to the exceptions register or buy list.
